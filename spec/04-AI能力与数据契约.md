## 0. 边界与不变量

| 术语 | 定义 |
|---|---|
| 契约键 | 病例 JSON 顶层键，共 **24 个** = 12 现有键 + 6 新增键 + 6 个 §4.2 承载键（01 §1.8 定义，本文接管校验） |
| 镜像键 | `physical_exam_findings` / `lab_and_imaging_reports`，双写期降级为新键的只读投影，供 `guardrail_engine` 读取 |
| 真值来源 | 同一数据新旧各一份时**以新键为准**；镜像由迁移脚本生成，校验器交叉核对 |
| 降级 | LLM 失败/超时/输出非法 → 静默回落模板。不抛异常、不弹框、不改判定 |

1. `INV-01` 病例相关判定数值（TAT、剂量、阈值、结局条件）只来自 JSON，代码里不得再有魔法数字。
2. `INV-02` 三能力在无 LLM 时必须走完整闭环；LLM 只改措辞，不改判据。
3. `INV-03` `validate_case()` 返回非空 ⇒ 进程不进入 `lifespan`，`/api/health` 不可达。这是验收第 10 条的唯一实现方式。
4. `INV-04` 老快照（`schema_version == 1`）必须能加载、续跑、结案；只读补默认值，不改写历史。
5. `INV-05` 情绪三档只按 `patient_trust` 判定，阈值 `0.70` / `0.30`，与焦虑解耦（01 §0.2）。
6. `INV-06` 说明书与导出内容的字段裁剪在**后端**完成，前端不做黑名单过滤。

### 1.2 现有 12 键逐字段

| 路径 | 类型 | 必填 | 约束 | 示例 |
|---|---|---|---|---|
| `case_id` | string | 是 | `^case_[a-z0-9_]{3,48}$`；全库唯一；**发布后不得改名**（`physiology_engine.py:21` 拿它当行为开关） | `"case_chest_pain_001"` |
| `title` | string | 是 | 6–80 字符；禁含 `{` `}` | `"生死时速：突发撕裂样胸痛…"` |
| `difficulty` | string | 是 | 2–40 字符；自由文案，不做枚举 | `"国家级学科竞赛 (Hard / High Stakes)"` |
| `difficulty_stars` | integer | 否 | `1..5`；缺省 `1`；缺失记 CM-502 warning | `4` |
| `category` | string | 是 | 2–60 字符 | `"急诊心血管胸痛三联征"` |
| `chief_complaint` | string | 是 | 8–120 字符；**必须含时间量词** `\d+\s*(小时\|分钟\|天\|周\|h\|min)`，否则 CM-401 | `"突发剧烈胸背部撕裂样疼痛伴大汗淋漓3小时"` |
| `patient_profile` | object | 是 | 8 字段，见下 | — |
| `initial_vitals` | object | 是 | 9 字段，见下 | — |
| `physical_exam_findings` | object | 是 | 6 个 legacy 键（`guardrail_engine.py:63-105` 硬编码读取），值为 `{title, findings, interpretation?}` | §1.5 |
| `lab_and_imaging_reports` | object | 是 | 键名自由；每个 `lab_panels[].name` 必须在此处**有对应报告**（CM-307）。2026-10-26 修订：原规则要求 report 带 `item_name`，但 guardrail 的 haystack 匹配与提问无关，带 `item_name` 会劫持后续查询，故改为以 `lab_panels` 为准 | §1.5 |
| `dialogue_scripts` | object | 是 | 至少含 `patient` / `family`；值为 string 或 array\<string\>；占位符只允许 `{order_name}` `{drug_name}` `{sbp}` `{dbp}` `{hr}`，其余报 CM-210 | — |
| `hemodynamic_rules` | object | 是 | 非夹层病例允许只写 `pattern` + `description`，下列四项缺省即生效 | — |

**`patient_profile`（8 字段）**：`.name` string 2–12；`.gender` 枚举 `男|女`；`.age` integer `0..120`；`.occupation` string 2–40；`.past_history` string ≥10；`.medication_history` array\<string\> ≥1（无用药史填 `["否认长期用药"]`）；`.allergy_history` string ≥4（阴性填 `"否认药物及食物过敏"`）；`.family_companion` string ≥3（无人陪同填 `"独自前来"`）。

**`initial_vitals`（9 字段）**：`.hr` number `20..250`；`.sbp` number `40..300`；`.dbp` number `20..200` 且 `< .sbp`；`.spo2` number `50..100`；`.rr` number `4..60`；`.pain_vas` integer `0..10`；`.temperature_c` number `33.0..43.0`（缺省 `36.8`）；`.ecg_rhythm` string ≥2；`.consciousness` string ≥2。

**`hemodynamic_rules`**：`target_hr_range` array\<number\> 长度 2、`lo<hi`、缺省 `[60,75]`；`target_sbp_range` 同理、缺省 `[100,120]`；`lethal_rupture_countdown_seconds` integer `30..600`、缺省 `120`；`uncontrolled_crisis_timeout_seconds` integer `60..1800`、缺省 `300`。

#### 1.2.1 镜像键映射

常量 `LEGACY_EXAM_KEY_MAP` 放 `app/core/case_schema.py`，**不写进 JSON**：`vitals_bilateral_bp`→`PE_BP_BILATERAL`、`heart_auscultation`→`PE_HEART_AUSCULTATION`、`lung_auscultation`→`PE_LUNG_AUSCULTATION`、`abdomen_exam`→`PE_ABDOMEN`、`peripheral_pulses`→`PE_PULSE`、`neuro_exam`→`PE_NEURO`。镜像为 `exam_options` 的**子集投影**：可以有镜像无选项；`required == true` 的选项必须有镜像。

### 1.3 §4.2 承载键（6 个）

| 键 | 类型 | 约束 |
|---|---|---|
| `present_illness` | object | 固定 5 键，均 string ≥4：`onset` 起病 / `character` 性质 / `radiation` 放射 / `trigger` 诱因 / `relief` 缓解因素 |
| `risk_factors` | array\<string\> | 长度 **≥3**（推荐 5），每项 ≥4 字符 |
| `key_positives` | array\<string\> | 长度 **恰为 3** |
| `key_negatives` | array\<string\> | 长度 **恰为 2** |
| `inquiry_points` | array\<string\> | 长度 **恰为 8**；每项是一句可判定的问诊意图（问什么），不是答案 |
| `differentials` | array\<object\> | 长度 **恰为 3**；每项 `{name, why_support, why_not}`，`name` ≥2 字符（容纳「急性阑尾炎」这类 5 字病名），其余两字段 ≥6 字符 |

### 1.4 六个新增键逐字段

#### 1.4.1 `emotion_scripts`（object，6 × 3 = 18 条）

键集合**恰好** `E1_CONSULT` / `E2_PAIN_DETAIL` / `E3_PHYSICAL` / `E4_WAIT_LAB` / `E5_RX` / `E6_PRE_OUTCOME`；每值为 object，键**恰好** `high` / `mid` / `low`，值 string 20–120 字符；档位判定 `high: trust ≥ 0.70`、`mid: 0.30 ≤ trust < 0.70`、`low: trust < 0.30`；禁止出现最终诊断名与具体药名剂量。

#### 1.4.2 `exam_options`（object[]）

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `exam_id` | string | 是 | `^PE_[A-Z0-9_]+$`；病例内唯一 |
| `name` | string | 是 | 必须能命中 `guardrail_engine.py:60-105` 的关键字组（01 §0.4） |
| `match_keywords` | array\<string\> | 是 | ≥3 项；**至少一项**与 `name` 互为子串（2026-10-26 修订：原文要求首项，与 §1.5 样例「周围血管搏动触诊」+ 首项「脉搏」自相矛盾） |
| `duration_seconds` | integer | 是 | ∈ `{30, 60, 90, 180, 300}` |
| `required` | boolean | 是 | `true` 计入「体查 5 项」必做清单 |
| `is_abnormal` | boolean | 是 | 本例该项有无阳性所见 |
| `findings` | object | 是 | 固定 2 键 `normal` / `abnormal`，均非空 string |
| `clinical_point` | string | 是 | 一句话说明「为什么值得花这几十秒」 |
| `guard_note` | string | 否 | 与其他部位查体易混淆时的排除说明 |

#### 1.4.3 `lab_panels`（object[]）

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `panel_id` | string | 是 | `^(LAB\|IMG)_[A-Z0-9_]+$`；病例内唯一 |
| `name` | string | 是 | 必须命中 `route_lab_or_imaging` 别名表（01 §0.4） |
| `alias` | array\<string\> | 是 | ≥2 项，含至少 1 个纯小写英文别名 |
| `modality` | enum | 是 | `ECG` / `LAB` / `IMAGING` / `ULTRASOUND` |
| `tat_seconds` | integer | 是 | `60..3600`；**必须等于总纲 §3.4 表值** |
| `is_key` | boolean | 是 | 属「检查 6 项」必开清单 |
| `is_gold_standard` | boolean | 是 | 每例**恰好 1 个** true（CM-305） |
| `is_trap` | boolean | 是 | 结果会诱导误诊的陷阱项 |
| `decision_window` | enum | 是 | `WITHIN_CLOCK` / `BEYOND_CLOCK` |
| `result_text` | string | 是 | 具体数值，禁 `约`/`左右`/`待查` |
| `ref_range` | string | 是 | 参考区间；影像类填 `"—"` |
| `conclusion` | string | 是 | 报告结论一句话 |
| `clinical_hint` | string | 是 | 教学提示，**不得直接说出最终诊断名** |

#### 1.4.4 `prescription_rules`（object[]）

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `rule_id` | string | 是 | `^RX_[A-Z0-9_]+$`；病例内唯一 |
| `drug_name` | string | 是 | 处方下拉显示名，病例内唯一 |
| `match_keywords` | array\<string\> | 是 | ≥1；`RED_LINE` 必须同时含中文名与 `config.py:191-202` 的英文名 |
| `verdict` | enum | 是 | `TARGET` / `SUPPORTIVE` / `WARN_ONLY` / `RED_LINE` / `OFF_LIST` |
| `dose` | string | 是 | 具体数值 + 单位 + 节奏，禁「适量」 |
| `route` | string | 是 | 静脉泵入 / 静脉推注 / 口服 / 雾化 / 舌下 |
| `frequency` | string | 是 | 具体频次 |
| `target` | string | 是 | 达标阈值，无靶目标填 `"—"` |
| `prerequisite` | string | 否 | `WARN_ONLY` 时**必填**（CM-204） |
| `consequence_text` | string | 是 | 命中后系统文案；红线须含致死机制 |
| `score_delta` | number | 是 | `-0.20..0.10`，对应总纲 §2.3 事件项 |

`verdict` 引擎动作：`TARGET` 加 `score_delta` 并推进状态机（正分）；`SUPPORTIVE` 加 `score_delta` 不改主状态（正分）；`WARN_ONLY` 弹护士拦截、不判死、`prerequisite` 未满足则扣分；`RED_LINE` 立即 `trigger_iatrogenic_rupture()` → 结局 D；`OFF_LIST` 拒绝开具、不消耗虚拟时间。

#### 1.4.5 `outcomes`（固定 4 键）

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| 顶层键 | — | 是 | 恰好 `A` / `B` / `C` / `D`（CM-309） |
| `.code` | string | 是 | 与键一致 |
| `.label` | string | 是 | A→治愈/稳定，B→延误，C→离院，D→死亡/不良事件 |
| `.condition` | string | 是 | 可判定布尔表达式；变量仅限 `HR` `SBP` `DBP` `SpO2` `RR` `trust` `anxiety` `has('N<nn>')` `has_red_line` `elapsed('...')` `outcome_of('...')` `negative_streak`，越界报 CM-310。**不交 LLM** |
| `.title` | string | 是 | ≤16 字符 |
| `.narration` | string | 是 | 60–160 字符 |
| `.patient_line` / `.family_line` | string | 是 | 各 ≥2 字符 |
| `.review_items` | array\<string\> | 是 | ≥3 项 |
| `.next_step` | string | 是 | ≥4 字符 |

#### 1.4.6 `knowledge_card`（object）

`title` string ≤20；`items` array 长度**恰为 5**；`items[].no` integer `1..5` 且与下标一致；`items[].title` ≤14 字符；`items[].one_liner` ≤60 字符；`items[].pitfall` 以 `常见误区：` 开头且 ≤60 字符。

## 2. 启动校验器规格

### 2.1 时机与阻断

| 项 | 规定 |
|---|---|
| 时机 | `case_repository._load_all()` 内，每个文件解析后立即校验；全部通过才注册 |
| 阻断 | 任一 `error` ⇒ 抛 `CaseValidationError` ⇒ `main.py` 不启动 uvicorn，退出码 `2` |
| 打印 | 首行 `病例校验失败：<N> 个文件、<M> 个错误`，随后每条缩进两格 |
| 不阻断 | `warning` 级（CM-5xx）只写 stderr，进程继续 |
| 与现状差异 | `case_repository.py:48-53` 的 `except (...): continue` **必须删除**（§8 C-01） |

### 2.2 函数签名


## 3. LLM 调用契约

### 3.1 参数（新增到 `config.py`）

| config 键 | 类型 | 值 | 说明 |
|---|---|---|---|
| `LLM_TIMEOUT_SECONDS` | float | **`8.0`** | 整次请求总超时（总纲 §6.2） |
| `LLM_CONNECT_TIMEOUT_SECONDS` | float | `3.0` | 建连超时，须小于总超时 |
| `LLM_MAX_RETRIES` | integer | **`0`** | 不重试。重试会把 8 秒变 16 秒，破坏计时 |
| `LLM_MAX_TOKENS` | integer | `300` | 单次生成上限 |
| `LLM_TEMPERATURE` | float | `0.6` | 保留角色感（判定不在 LLM） |
| `LLM_DEGRADED_NOTICE` | string | `"离线模式"` | UI 角标文案 |

调用写法固定为 `httpx.Client(timeout=httpx.Timeout(LLM_TIMEOUT_SECONDS, connect=LLM_CONNECT_TIMEOUT_SECONDS))`。

### 3.2 唯一入口

| 约束 | 规定 |
|---|---|
| 入口 | 仅 `AgentEngine._generate_llm_response()` 与 `_generate_multi_agent_llm_response()` |
| 返回 | 成功返回内容；**任何失败返回 `None`，不抛异常** |
| 调用方 | 拿到 `None` 必须走模板分支，不得中断请求 |
| 禁用 | `GEDEvaluator` / `GuardrailEngine` / `PhysiologyEngine` / `routes_*.py` 内禁止直接 httpx |

### 3.3 失败静默降级序列

```
① is_online_llm_active() == False      ⇒ 直接模板，不发请求
② 发起请求，开始计时
③ 超时 / 连接失败 / HTTP != 2xx / JSON 解析失败 / 内容为空
     ⇒ 记 LLM_LAST_ERROR（仅内存）、会话 llm_degraded=True
     ⇒ 返回 None
④ 调用方落模板文案（dialogue_scripts / emotion_scripts）
⑤ WS 下一帧带 "llm_mode": "offline"
⑥ UI 角落显示「离线模式」角标
```

硬约束：**不弹错误框、不改 HTTP 状态码、不在对话流插报错文本、不因 LLM 失败影响评分与结局。**

### 3.4 绝不交给 LLM 的判定

| # | 判定 | 唯一权威 | 为什么不能交 LLM |
|---|---|---|---|
| G1 | 六维雷达分与总分 | `ged_evaluator.evaluate()`（`ged_evaluator.py:116,215-246`）| **不可复现**：同一串动作两次调用分数不同，无法申诉、无法回归 |
| G2 | 红线药物判定 | `prescription_rules[].verdict` + `physiology_engine.apply_medication()`（`:77`）| **不可测试**：判定必须能写成断言；模型对「阿司匹林是否致命」的回答随温度漂移 |
| G3 | 死亡 / 心脏骤停 | `physiology_engine` 状态机（`S6_CARDIAC_ARREST`）| **不可解释**：死因必须逐条指认到具体时刻与医嘱 |
| G4 | 离院结局 | `patient_trust` 阈值 + 持续计时（总纲 §1.3）| 同上，且模型读不到每秒状态 |
| G5 | 检查结果数值 | `lab_panels[].result_text` 原文 | **不可复现**：模型生成的数值会让同名检查在两例间不一致 |
| G6 | TAT 与检查耗时 | `lab_panels[].tat_seconds` / `exam_options[].duration_seconds` | 时间轴是评分基准，必须常量 |
| G7 | 情绪数值 | `EmotionEngine`（02 §1）| 每秒结算，8 秒延迟不可接受 |
| G8 | 三档文案选择 | `patient_trust` 阈值 | 选档必须可断言 |
| G9 | 结局 `condition` 求值 | `outcomes.*.condition` 表达式求值器 | 表达式引擎确定性；模型只能读结果 |
| G10 | 说明书内容 | 后端白名单裁剪（§6.2 C）| 泄题风险：写什么由字段白名单决定 |

### 3.5 允许 LLM 做的（仅措辞层）

输入必须是**已确定的事实包**，输出只能是这些事实的中文表述：

```json
{
  "facts": {"patient_name": "孙建国", "age": 52, "pain_vas": 9, "hr": 108, "sbp": 195,
            "emotion_tier": "mid", "last_doctor_action": "询问疼痛是否向背部放射",
            "allowed_say": ["撕裂样痛", "向后背放射", "含硝酸甘油无效"]},
  "constraints": {"max_chars": 60, "must_not_say": ["主动脉夹层", "Stanford", "CTA", "阿司匹林", "mg"]}
}
```

三条红线：不得新增事实、不得说出诊断名、不得给出剂量。

### 3.6 输出后置校验（三道闸）

| 闸 | 规则 | 命中处理 |
|---|---|---|
| A1 长度 | 40–300 字 | 丢弃 → 模板 |
| A2 禁词 | 诊断名词表（`主动脉夹层`/`Stanford`/`心肌梗死`/`肺栓塞`）+ 剂量正则 `\d+\s*(mg\|µg\|g\|mL\|U)` | 丢弃 → 模板 |
| A3 结构 | 多角色分支必须返回 `{patient, family}` 合法 JSON | 丢弃 → 模板 |

丢弃后日志记 `llm_rejected reason=A2`，**不向 UI 报错**。

### 5.3 迁移方案（老会话无新字段）

```python
# session_manager.py 加载分支
def _upgrade_snapshot(data: dict) -> dict:
    if int(data.get("schema_version", 1)) < 2:
        data.setdefault("emotion_log", [])
        data.setdefault("leave_reason", None)
        data.setdefault("outcome_code", None)
        data.setdefault("llm_degraded", None)
        ag = data.setdefault("agent_state", {})
        ag.setdefault("patient_anxiety", config.EMOTION_INIT_PATIENT_ANXIETY)
        ag.setdefault("refused_exams", [])
        ag.setdefault("anxiety_cap_seconds", 0)
        ag.setdefault("negative_streak", 0)
        ag.setdefault("trust_low_seconds", 0)
        data["schema_version"] = 2
    return data
```

三条保证：① **不写回**——加载只读补齐，`persist()` 仅在会话有动作时覆盖，老快照原样留库；② **Pydantic 兜底**——`AgentState` 新字段一律给默认值，漏补也不抛；③ **存在即尊重**——已有 `patient_anxiety` 不覆盖（可能来自新版本写入但版本号未更新）。

DDL 增量（幂等）：`PRAGMA table_info(sessions)` 判 `schema_version` 列是否存在，缺则 `ALTER TABLE sessions ADD COLUMN schema_version INTEGER NOT NULL DEFAULT 1`；再 `CREATE INDEX IF NOT EXISTS idx_sessions_updated ON sessions(updated DESC)`。

5. **派生六个新键**：`emotion_scripts` 由 `dialogue_scripts` 现有文案映射到 `E1/E2/E5/E6`，`E3/E4` 由 `CURATED` 补，缺档用 `mid` 兜底并记 `PARTIAL_MID`；`exam_options` 由 6 个镜像键 + `game_extensions.required_exams` 生成，`exam_id` 由 `LEGACY_EXAM_KEY_MAP` 反查；`lab_panels` 由 `lab_and_imaging_reports` 逐项生成，`tat_seconds` 取 `report_time_seconds`（**与总纲 §3.4 冲突时以总纲为准**，§8 C-05），`is_key` 前 6 项为 true，`is_gold_standard` 由 `CURATED` 指定；`prescription_rules` 由 `game_extensions.treatment_plan.medications`（`TARGET`/`SUPPORTIVE`）+ `contraindications`（`RED_LINE`）生成，夹层例以 `config.LETHAL_MEDICATION_KEYWORDS` 为红线底表；`outcomes` 与 `knowledge_card` 必须由 `CURATED` 提供（`game_extensions.core_teaching` 只有一句话，不足以生成 5 条），缺失则**不写盘**并报 `NEEDS_AUTHORING`。
6. **写盘**：`json.dump(doc, f, ensure_ascii=False, indent=2)` + 末尾换行，键序按 §1.1 排序。
7. **自检**：重新 `json.load` + `validate_case`；任一 error → 从 `.backup-<ts>` 恢复该文件并退出码 `1`。
8. **索引**：更新 `index.json` 的 `version` / `schema_version`，不改 `case_id` / `file` / `name`。
