### 1.5 30 秒趋势箭头算法

| 项 | 规定 |
|---|---|
| 窗口 | **30 秒**；后端 5 秒结算 → 窗口内 6 个样本 |
| 载体 | 每通道一条定长环形缓冲 `emotionHist[key]`，长度 **7**（6 历史 + 当前） |
| 压入时机 | 仅 `emotion_rev` 变化时压入 `{t: virtual_seconds, v}`；**不随 1 Hz 遥测压入** |
| 基准点 | 缓冲区中 `≤ now-30` 且最接近 `now-30` 的样本；样本跨度 <30 s → **不显示箭头** |
| 判定 | `d = v_now − v_base`；`|d| < 0.02` → 平；`d ≥ +0.02` → `↑`；`d ≤ −0.02` → `↓`（阈值 0.02 ≈ 2 个百分点） |
| 显示 | 跨度满 30 s 才加 `scene-trend-shown`（否则 `opacity:0` + `aria-hidden="true"`） |
| 方向着色 | `↑` 对信任度是**好**（`scene-trend-good`），对两条焦虑是**坏**（`scene-trend-bad`）；`↓` 反之 |
| 语义 | 可见时写 `aria-label="信任度较 30 秒前上升 3 个百分点"`，箭头字符本身 `aria-hidden` |

### 1.6 200 ms 过渡实现要点

| 项 | 规定 |
|---|---|
| 条宽 | `fill.style.width = (v*100).toFixed(1)+'%'`，CSS `transition:width 200ms linear` |
| 颜色 | 换带不跳变：`transition:background-color 200ms linear`，靠 `scene-band-*` 类切换触发 |
| 数字 | 只在 `Math.round(v*100)` 变化时写 `textContent`（0.005 的最小增量不足以改整数百分比时，数字**不动**，只有条宽微动） |
| 禁止 | 不得用 `requestAnimationFrame` 逐帧补间条宽；不得用 `setTimeout` 链模拟缓动 |
| 写序 | 同一帧内：先 `width` → 再切 `scene-band-*` → 再写数字，避免"数字已变、条还没走" |

### 2.3 明确不显示死亡倒计时

| 项 | 结论 |
|---|---|
| 是否显示"距恶化/死亡还有 X 秒" | **不显示** |
| 理由①剧透 | 倒计时等于把答案写给学生：知道还有 8 分钟，训练就退化为"卡点操作"，目标从临床推理异化为读表 |
| 理由②注意力 | 数字倒数持续吸引视线，挤占对生命体征与病史的关注；主指标是决策质量而非手速 |
| 理由③有替代 | 三档色标已能传达"在变坏"且不泄露阈值；TAT 条传达的是**自己造成的等待成本**，这才是教学点 |
| 现状冲突 | `scene.js:226` 当前就在渲染 `倒计时 ${snapshot.rupture_countdown} 秒`，必须删除该分支（B2） |
| 允许显示的时间 | ①病程已用时长 `MM:SS` ②各检查剩余 TAT `MM:SS` ③记录条目的虚拟时间点。三者都是**已投入**而非"未来大限" |

### 8.4 与现有 1 Hz 渲染循环的关系

现状（已核）：`scene.js:168-201` 是 `requestAnimationFrame` 波形循环（≈60 fps）；`scene.js:202-235` 的 `telemetry()` 由 WebSocket `vitals_update` 驱动（1 Hz，`scene.js:321`）；`scene.js:341` 另有 `setInterval(…,1000)` 做 6 秒断流检测。**不存在独立的"1 Hz 渲染循环"**。

| 层 | 频率 | 职责 | 本次改动 |
|---|---|---|---|
| 波形层（rAF） | ~60 fps | ECG/PLETH/RESP 折线 | **不动** |
| 遥测层（WS） | 1 Hz | 生命体征、计时、雷达、情绪 | 追加 `renderPhaseBadge`/`renderTaskProgress`/`renderRefusal` |
| 情绪层（后端） | 0.2 Hz（5 秒） | 三通道结算 | 只在 `emotion_rev` 变化时重绘面板 |
| 过渡层（CSS） | 200 ms / 1 s | 条宽与颜色平滑 | 纯 CSS，无 JS 补间 |

```js
// 追加在 telemetry() 末尾（scene.js:234 的 updateSpeech() 之后）
if (snapshot.emotion_rev !== lastEmotionRev) {
  lastEmotionRev = snapshot.emotion_rev;
  pushEmotionSample(snapshot.virtual_seconds || 0, snapshot.emotion || {});
  renderEmotionPanel(snapshot); renderRecords(snapshot);
}
if (snapshot.phase !== lastPhase) { lastPhase = snapshot.phase; renderPhaseBadge(snapshot); }
renderTaskProgress(snapshot);   // 内部比对签名，无变化早退
renderRefusal(snapshot);        // 同上
```

| 规则 | 说明 |
|---|---|
| 不新增定时器 | 除 `startEmotionTicker()` 的 1 Hz 轻量 tick（只算箭头）外，不得再起 `setInterval` |
| 不每帧写 DOM | 上述函数首行必须做签名比对（`lastTraceSig`），无变化直接 `return` |
| 不阻塞波形 | 新函数必须是同步、无 `await` 的纯 DOM 写入；任何 `fetch` 一律不进这条路径 |
| 结算与呈现解耦 | 学生感知的"实时"来自 200 ms CSS 过渡，不靠提高结算频率；后端仍 5 秒 |

## 9. 响应式

### 9.1 舞台事实（决定响应式只能这么做）

| 事实 | 数值 | 影响 |
|---|---|---|
| `.canvas` 逻辑尺寸 | 固定 `1600×900`（`scene.css:11`） | 布局不回流，只整体缩放 |
| 缩放算法 | `scale(min(innerWidth/1600, innerHeight/900))`（`scene.js:59`） | 视口越窄字越小 |
| 1280×720 | `scale = 0.8` | 12 px 字 → **9.6 实际 px**，偏小 |
| 1920×1080 | `scale = 1.2` | 12 px → 14.4 实际 px，舒适（1600×1.2 / 900×1.2 恰好铺满） |
| 媒体查询基准 | **视口宽度**，不是舞台宽度 | `@media` 在此是"可读性开关"，不是"重排开关" |

> 结论：响应式目标不是重排（舞台固定），而是**窄屏放大关键信息、砍次要信息**；所有 `@media` 只切换组件变体类。
