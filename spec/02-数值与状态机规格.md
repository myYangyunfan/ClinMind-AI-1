## 0. 术语与不变量

| 术语 | 定义 |
|---|---|
| 时间项 | 每 `EMOTION_SETTLE_INTERVAL_S` 秒自动施加的基础变化，只受上下限约束 |
| 事件项 | 由玩家动作/系统事件触发的一次性变化，不受上下限约束，可把值推到 0.0 或 1.0 |
| 结算 | 一次 `_settle_once()` 调用：施时间项 + 评估乘数 + 裁剪 + 判阈值 + 写日志 |
| 标称时长 | 不含联动乘数、仅按时间项速率算出的触底/触顶时间 |
| 实测时长 | 含 §1.4 联动乘数的真实触底/触顶时间（测试断言用这个） |

**不变量（违反即视为实现错误）**

1. `INV-01` 时间项永不把 `patient_trust` 压到 `EMOTION_TIME_TRUST_FLOOR` 以下，也永不把 `patient_anxiety` / `family_anxiety` 抬到 `EMOTION_TIME_ANXIETY_CEIL` 以上。
2. `INV-02` 时间项单独作用时，**永不**触发离院、永不触发拒绝配合。抵达 0.05 / 0.10 / 0.90 / 0.95 这四条线必须存在事件项贡献。
3. `INV-03` 所有 `[0,1]` 裁剪发生在**乘数之后**，且 `clamp` 本身记为一次 `CLAMP` 来源日志。
4. `INV-04` 死亡（`S6_CARDIAC_ARREST`）是终态；进入终态后 `tick_emotion()` 立即空转，不再写任何 delta 记录。
5. `INV-05` 引擎内禁止魔法数字，全部经 `config.EMOTION_*` 读取（总纲 §2.1）。

**乘数合成规则（唯一合法顺序，禁止实现方自创）**

```
信任衰减乘数 = 1.0
  若 anxiety_now >= EMOTION_MULT_ANXIETY_TRIGGER:      ×= EMOTION_MULT_TRUST_DECAY_HIGH_ANXIETY
  若 critical_hold_seconds >= EMOTION_MULT_CRITICAL_HOLD_S: ×= EMOTION_MULT_CRITICAL_DECAY
  信任衰减乘数 = min(信任衰减乘数, EMOTION_MULT_TOTAL_CAP)

焦虑增长乘数 = 1.0
  若 trust_now >= EMOTION_MULT_TRUST_TRIGGER:      ×= EMOTION_MULT_ANXIETY_GROWTH_HIGH_TRUST
  若 trust_now <= EMOTION_MULT_TRUST_LOW_TRIGGER:  ×= EMOTION_MULT_ANXIETY_GROWTH_LOW_TRUST
```

> 乘数一律使用**本轮结算开始时的快照值**（`trust_prev` / `anxiety_prev`），不得用本轮刚算出的新值，否则同帧内会自激。高信任与低信任两条互斥（`0.70 > 0.20`），若配置被改成重叠区间，取「低信任」那条并写 `WARN` 日志。

## 2. 结算算法

### 2.1 数据流

```
1 Hz tick_all() ─┬─ physiology_engine.advance_time(1.0)   既有，不动
                 └─ emotion_engine.tick_emotion(1.0)     新增，内部 5 s 累加器
                       └─ 每满 5.0 s → _settle_once()：算乘数 → 施时间项 → 裁剪 → 判阈值 → 写账
```

生理与情绪**不同频**：生理 1 Hz，情绪 5 s 一次。原因是情绪是慢变量，5 s 一次既够平滑又能把 CPU 压到总纲 §7.3 的 5% 以下。

### 2.2 `tick_emotion(dt)` 伪代码

```python
def tick_emotion(self, dt: float) -> int:
    """Session 级入口。dt 为本次推进的虚拟秒数（通常 1.0）。返回本次结算次数。"""
    if self.is_finished or self.terminal_reason != TerminalReason.NONE or dt <= 0.0:
        return 0                                              # INV-04：终态/空步空转
    self._emotion_accumulator += dt                           # 唯一时间源，禁读 time.time()

    if self._emotion_accumulator > config.EMOTION_MAX_BACKLOG_S:   # 断连回来防雪崩
        self.log_settle_skipped(self._emotion_accumulator - config.EMOTION_MAX_BACKLOG_S)
        self._emotion_accumulator = config.EMOTION_MAX_BACKLOG_S

    settled, step = 0, config.EMOTION_SETTLE_INTERVAL_S
    while (self._emotion_accumulator + config.EMOTION_FLOAT_EPS >= step
           and settled < config.EMOTION_MAX_CATCHUP_STEPS):
        self._emotion_accumulator -= step
        self._settle_once()
        settled += 1
        if self.terminal_reason != TerminalReason.NONE:       # 死亡/离院即停，丢弃余量
            self._emotion_accumulator = 0.0
            break

    if settled >= config.EMOTION_MAX_CATCHUP_STEPS:           # 命中补算上限：丢弃残余
        self._emotion_accumulator = 0.0
        self.log_settle_skipped(step)
    return settled
```

### 2.3 `_settle_once()` 伪代码（核心，逐行可翻）

```python
def _settle_once(self) -> None:
    st = self.agent_engine.state
    prev_trust   = st.patient_trust
    prev_anxiety = st.patient_anxiety
    prev_family  = st.family_anxiety
    vsec = self.virtual_seconds

    # ---------- A. 快照上算乘数（禁止用本轮新值） ----------
    mult_trust = 1.0
    if prev_anxiety >= config.EMOTION_MULT_ANXIETY_TRIGGER - EPS:
        mult_trust *= config.EMOTION_MULT_TRUST_DECAY_HIGH_ANXIETY
    if self._critical_anxiety_hold_s >= config.EMOTION_MULT_CRITICAL_HOLD_S - EPS:
        mult_trust *= config.EMOTION_MULT_CRITICAL_DECAY
    mult_trust = min(mult_trust, config.EMOTION_MULT_TOTAL_CAP)

    mult_anx = 1.0
    if prev_trust >= config.EMOTION_MULT_TRUST_TRIGGER - EPS:
        mult_anx *= config.EMOTION_MULT_ANXIETY_GROWTH_HIGH_TRUST
    elif prev_trust <= config.EMOTION_MULT_TRUST_LOW_TRIGGER + EPS:
        mult_anx *= config.EMOTION_MULT_ANXIETY_GROWTH_LOW_TRUST

    # ---------- B. 时间项：只在本侧开区间内生效 ----------
    d_trust = 0.0
    if prev_trust > config.EMOTION_TIME_TRUST_FLOOR + EPS:
        d_trust = -config.EMOTION_TIME_TRUST_DECAY * mult_trust

    d_anx = 0.0
    if prev_anxiety < config.EMOTION_TIME_ANXIETY_CEIL - EPS:
        d_anx = +config.EMOTION_TIME_ANXIETY_RISE * mult_anx

    d_family = 0.0
    if prev_family < config.EMOTION_TIME_FAMILY_CEIL - EPS:
        d_family = +config.EMOTION_TIME_FAMILY_RISE

    # ---------- C. 施加 + 裁剪 ----------
    # pin(bound, v, d)：d 指向该边界且已越界时返回 bound，否则返回 v，保证 0.15/0.85 是精确值
    new_trust   = pin(config.EMOTION_TIME_TRUST_FLOOR,  clamp01(prev_trust   + d_trust),  d_trust)
    new_anx     = pin(config.EMOTION_TIME_ANXIETY_CEIL, clamp01(prev_anxiety + d_anx),    d_anx)
    new_family  = pin(config.EMOTION_TIME_FAMILY_CEIL,  clamp01(prev_family  + d_family), d_family)
    st.patient_trust, st.patient_anxiety, st.family_anxiety = new_trust, new_anx, new_family

    # ---------- D. 危重焦虑持时（新值续期；乘数用的是旧值，见 A 步） ----------
    self._critical_anxiety_hold_s = (self._critical_anxiety_hold_s + config.EMOTION_SETTLE_INTERVAL_S
                                     if new_anx >= config.EMOTION_MULT_CRITICAL_ANXIETY - EPS else 0.0)

    # ---------- E. 阈值判定（顺序=优先级，见 §3.4） ----------
    self._update_emotion_state()     # 稳定 / 焦躁 / 拒绝配合
    self._update_departure_watch()   # 0.10 持续计时

    # ---------- F. 日志：工程账必写，玩家可见流受 0.005 抑制 ----------
    self._log_delta("patient_trust",   prev_trust,   new_trust,   "TIME_TERM", "E00_SETTLE", mult_trust)
    self._log_delta("patient_anxiety", prev_anxiety, new_anx,     "TIME_TERM", "E00_SETTLE", mult_anx)
    self._log_delta("family_anxiety",  prev_family,  new_family,  "TIME_TERM", "E00_SETTLE", 1.0)
```

```python
def _log_delta(self, metric, before, after, source, event, mult):
    delta = after - before
    if abs(delta) < config.EMOTION_FLOAT_EPS:
        return                                  # 真的没动，不写
    entry = EmotionLogEntry(
        virtual_seconds=self.virtual_seconds,
        metric=metric, value_before=before, delta=delta, value_after=after,
        trigger_event=event, source_module=source, multiplier=mult,
        silent=(abs(delta) < config.EMOTION_DELTA_EPSILON),
    )
    self._append_ledger(entry)                  # 工程账：无条件写（INV 见 §5.2）
    if not entry.silent:
        self.emotion_events.push(entry)         # 玩家可见流：>= 0.005 才推
```

### 2.4 关键约定

| 约定 | 规则 | 理由 |
|---|---|---|
| 时间项与上下限 | 只在开区间生效，**不**对事件项生效 | 总纲 §2.4 注：事件必须能推到 0 / 1 |
| 0.005 抑制的作用域 | 只抑制 **UI 提示** 与 `emotion_events`；`emotion_ledger` 照写 | 时间项单次只有 0.004，若全抑制则永远不降，验收 1 直接失败（见 §7 C-04） |
| 乘数快照 | 一次结算内，所有乘数用 `prev_*` | 防止同帧自激 |
| 裁剪 | `[0,1]` 硬裁；时间项边界用精确赋值 | 让断言 `== 0.15` 成立，不用 `approx` |
| 时钟 | 只用 `virtual_seconds` 与累加器，禁用 `time.time()` | 暂停/重连可复现，测试可确定性推进 |
| 冻结 | `terminal_reason != NONE` 或 `is_finished` 时返回 0 | 终态不写账，避免复盘噪声 |

### 2.5 与现有 1 Hz `tick_all` 的接入

改动点（仅说明，不落地）：

```python
# session_manager.py: SimulationSession.tick() —— 原 return 改成分两步
def tick(self, dt: float = 1.0) -> VitalsVector:
    if not self.is_active or self.is_finished:
        return self.physiology_engine.get_current_vitals()
    self.virtual_seconds += int(dt)
    self.physiology_engine.advance_time(dt)      # ← 既有，不动
    self.emotion_engine.tick_emotion(dt)         # ← 新增：内部 5 s 累加
    return self.physiology_engine.get_current_vitals()

# session_manager.py: SessionStore.tick_all() —— 循环体加锁
for session in list(self._sessions.values()):
    ...
    if session.is_active and not session.is_finished:
        with session.lock:                       # ← 新增
            session.tick()
            session.spontaneous_dialogues = session.agent_engine.check_spontaneous_events(...)
        ...
```

顺序固定为：**先生理、后情绪、再事件**。理由：死亡判定依赖 `physiology_engine.state`，同一秒内必须先让生理有机会进入 S6，情绪才能立即冻结；反过来会出现「死亡当秒还扣了一次信任」的脏账。

### 2.6 线程安全

| 风险点 | 现状 | 方案 |
|---|---|---|
| `tick_all` 与 HTTP 处理器并发写 `AgentState` | FastAPI 的 `def` 路由跑在线程池，`tick_all` 跑在事件循环，二者可同时命中同一 session | `SimulationSession.lock = threading.RLock()`；`tick()`、`apply_emotion_event()`、`persist()` 三处统一 `with self.lock` |
| `emotion_engine` 与 `agent_engine` 双写 `patient_trust` | 事件走 agent_engine，时间项走 emotion_engine | 事件也只写 `agent_engine.state`；emotion_engine 不持有副本，避免双份真值 |
| 日志列表并发 append | `list.append` 在 CPython 下原子但不保证顺序一致 | 在锁内 append；`_append_ledger` 用环形 `collections.deque(maxlen=EMOTION_LOG_CAP)` |
| 多 worker 部署 | 当前 uvicorn 单进程，`SessionStore` 是进程内单例 | 规格约束：**必须 `--workers 1`**；否则同一 session 会被两个进程各推一份时钟。启动时检测 `WEB_CONCURRENCY > 1` 直接 fail-fast |
| 重入 | `_settle_once` 内部调用 `_update_emotion_state`，后者可能写日志 | 统一用 `RLock` 而非 `Lock` |

### 2.7 暂停 / 重连补算

| 场景 | 行为 |
|---|---|
| 浏览器标签页关闭后重开 | 服务端 `tick_all` 不停，无需补算；`virtual_seconds` 连续 |
| 服务重启（从 sqlite 恢复） | 恢复 `_emotion_accumulator`、`_critical_anxiety_hold_s`、`_departure_watch_s` 三个字段；**不**按墙钟差值补算（重启期间患者状态未知，补算是编造） |
| 前端手动暂停（若实现） | 只停 UI 轮询，服务端照走；总纲 §5.3 已定「说明书弹窗不暂停计时」 |
| 恢复时缺口 > `EMOTION_MAX_BACKLOG_S` | 只补 300 s，写 `SETTLE_SKIPPED` 日志，复盘时间线断开处打标记 |
| 补算期间跨过死亡 | 第一次 `_settle_once` 后 `is_finished` 置位，`break` 并清空累加器（不补剩下的步） |

**持久化字段**：`SessionStore.persist()` 的 `snapshot` 必须新增 `"emotion"` 子字典，含 `accumulator` / `critical_anxiety_hold_s` / `departure_watch_s` / `emotion_state` / `terminal_reason` / `neg_interaction_streak` / `last_settled_virtual_seconds` 七个键。

## 3. 状态机

### 3.1 情绪状态定义

### 3.2 生理阶段（既有代码事实）

|---|---|---|
| S0 | `S0_STABLE` | 初始 |
| S1 | `S1_HYPERTENSION_CRISIS` | `elapsed_seconds > 300` 且无 β 阻滞剂/扩血管药（L193） |
| S2 | `S2_PHARMACO_CONTROLLED` | `beta_blocker_active and vasodilator_active`（L275） |

### 3.3 合成迁移表（生理 × 情绪）

优先级 `P0 > P1 > P2 > P3 > P4`；同帧只允许一条迁移生效，按优先级从高到低匹配，命中即停。

| # | 当前（生理, 情绪） | 触发条件 | 迁移到 | 优先级 | 副作用 |
|---|---|---|---|---|---|

| T02 | `(S0~S5, EMO_STABLE)` | `anxiety >= 0.70` | `(同, EMO_AGITATED)` | P3 | 回答变短 |

| T10 | `(S0~S2, 任意)` | 开禁忌药 | `(S3, 同)` | — | 既有 `trigger_iatrogenic_rupture` |
| T11 | `(S3→S4→S5→S6, 任意)` | 既有倒计时 | 逐级 | — | 死亡 165 s 级联 |
| T12 | `(S4/S5, 任意)` | 意识丧失 | 情绪不变但**冻结非处置类事件** | P2 | 问诊返回固定文案（`agent_engine.py:56-71`），记 E15 |
| T13 | `(S6, EMO_FROZEN)` | 任何后续请求 | 不迁移 | P0 | 返回 410 + 结局 D |

| T16 | `(S6, EMO_DEPARTED)` | 理论不可达（T01 先命中） | `DEATH` 优先 | P0 | 冲突时以死亡为准，写 `CONFLICT` 日志 |

**互斥关系**

- `EMO_FROZEN` 与 `EMO_DEPARTED` 互斥：死亡后不再离院。
- `S6` 与 `EMO_STABLE/AGITATED/REFUSING` 互斥：进入 S6 立即转 `EMO_FROZEN`。
- `EMO_REFUSING` 与 `S4/S5/S6` 互斥：意识丧失后「拒绝」无意义，T12 直接压掉。
- `terminal_reason` 是**单值枚举**，后写不覆盖先写（`DEATH` 一旦置位，`DEPARTURE` 写入被拒并记 `CONFLICT`）。

### 3.4 优先级与判定时序

```
每 5 s 结算末尾：
  1. 若 physiology.state == S6            → DEATH，停（P0）
  2. 若 terminal_reason == NONE 且 离院条件成立 → DEPARTURE，停（P1）
  3. 否则按 anxiety 更新 稳定/焦躁/拒绝配合（P2~P4）
```

三条线**不在同一层**：死亡来自生理模块，离院来自信任累积，拒绝配合来自焦虑瞬时值。把它们塞进同一个 `if/elif` 链是错的——死亡与离院可以同时成立（信任已崩但心搏也停了），这时必须是死亡。

### 3.5 「离院」与「死亡」如何区分

`is_finished` 现在是**语义垃圾桶**：`routes_eval.py:27-28` 交卷时置 `True`，`session_manager.py:55/139` 用它当「停表」布尔。改造方案：

| 新增字段 | 类型 | 取值 | 用途 |
|---|---|---|---|
| `session.terminal_reason` | `TerminalReason` 枚举 | `NONE` / `DEATH` / `DEPARTURE` / `EVALUATED` | 唯一权威的终止原因 |
| `session.outcome` | `OutcomeEnum` | `A_STABLE` / `B_DELAYED` / `C_DEPARTED` / `D_DEATH` / `IN_PROGRESS` | 呈现层，供结案页与复盘 |
| `session.is_finished` | bool | 保持不变，仅作**派生值**：`terminal_reason != NONE` | 兼容既有路由，不改语义边界 |

派生规则：

```python
session.is_finished = session.terminal_reason != TerminalReason.NONE
```

这样 `routes_action.py:23`（`if session.is_finished`）继续生效，但响应体要带上 `terminal_reason` 与 `outcome`，前端才分得清「死了」「走了」「交卷了」。

## 4. 三条判定线

### 4.1 判定式（可直接翻成 if）

```python
EPS = config.EMOTION_FLOAT_EPS

# ---------- 线 1：死亡（P0） ----------
def is_dead(session) -> bool:
    return (session.physiology_engine.state == PatientStateEnum.S6_CARDIAC_ARREST
            or session.physiology_engine.fatal_death_occurred)

# ---------- 线 2：离院（P1） ----------
def should_depart(session) -> bool:
    if is_dead(session):
        return False                                   # 死亡优先，二者互斥
    trust = session.agent_engine.state.patient_trust
    if trust <= config.EMOTION_TH_TRUST_DEPART_IMMEDIATE + EPS \
       and session.emotion_engine.neg_interaction_streak >= config.EMOTION_NEG_WINDOW:
        return True                                    # 立即离院
    return (trust <= config.EMOTION_TH_TRUST_DEPART_SUSTAINED + EPS
            and session.emotion_engine.departure_watch_s
                >= config.EMOTION_TH_TRUST_DEPART_HOLD_S - EPS)   # 持续离院

def update_departure_watch(session, dt):
    if session.agent_engine.state.patient_trust <= config.EMOTION_TH_TRUST_DEPART_SUSTAINED + EPS:
        session.emotion_engine.departure_watch_s += dt
    else:
        session.emotion_engine.departure_watch_s = 0.0   # 一旦回升立刻清零，不累计

# ---------- 线 3：拒绝配合（P2） ----------
def is_refusing(session) -> bool:
    return session.emotion_engine.emotion_state == EmotionState.EMO_REFUSING

def refuse_check_roll(session) -> bool:
    if not is_refusing(session):
        return False
    if session.physiology_engine.state in (S4, S5, S6):
        return False                                   # 意识丧失，谈不上拒绝
    return random.random() < config.EMOTION_TH_REFUSE_CHECK_PROB
```

**负面交互计数**：`neg_interaction_streak` 在每次事件 δ 使 `Δtrust < 0` 时 `+1`，使 `Δtrust > 0` 时归 `0`，`Δtrust == 0`（E08/E15）时**不变**。窗口是「最近 N 次交互」，所以是连续的 streak，不是计数器。

### 4.2 边界值用例（恰好等于阈值怎么算）

| 用例 | 输入 | 期望 | 判定口径 |
|---|---|---|---|
| B01 信任恰好 `0.15` | 时间项推到 `0.1499999` | 精确置 `0.15` 并停住，**不**触发离院 | 时间项 `>` floor 才生效 |
| B02 焦虑恰好 `0.85` | 时间项累计到 `0.8501` | 精确置 `0.85` 并停住 | 时间项 `< ceil` 才生效 |
| B03 焦虑恰好 `0.90` | `anxiety == 0.90` | **进入** `EMO_REFUSING` | 阈值用 `>=`（含端） |
| B04 焦虑恰好 `0.70` | `anxiety == 0.70` | **进入** `EMO_AGITATED`，且信任乘数 `×1.5` 生效 | `>=` |
| B05 信任恰好 `0.05` | `trust == 0.05` 且 `neg_streak == 3` | **立即离院** | `<=` |
| B06 信任 `0.0501` | `trust == 0.0501`、`neg_streak == 3` | 不离院 | `<=` 且 `EPS` 内不放宽 |
| B07 信任恰好 `0.10` | `trust == 0.10` | `watch` 开始计时 | `<=` |
| B08 持续恰好 `60.0 s` | `watch == 60.0` | **离院**（12 次结算） | `>=`，用 `EPS` 吸收浮点 |
| B09 持续 `55 s` | `watch == 55.0` | 不离院 | 差 5 s |
| B10 焦虑 `0.80` 在拒绝态 | `0.80` | **仍拒绝**（滞回区），`0.7999` 才退出 | 退出用 `<`，硬边界 |
| B11 δ 恰好 `0.005` | `|delta| == 0.005` | **产生** UI 提示 | 抑制条件是 `<`，不含端 |
| B12 δ `0.0049` | 时间项单步 | 只写工程账，不推 UI | `<` |
| B13 死亡当秒仍有事件 | 同帧先 S6 后动作 | 动作 410，delta 不写 | T01 优先 |
| B14 离院当秒仍有检查 | `EMO_DEPARTED` + 下单 | 409，但**不**记 E14 | T14 |

**浮点比较规范（强制）**

```python
def ge(a, b): return a >= b - config.EMOTION_FLOAT_EPS
def le(a, b): return a <= b + config.EMOTION_FLOAT_EPS
def lt(a, b): return a <  b - config.EMOTION_FLOAT_EPS
def gt(a, b): return a >  b + config.EMOTION_FLOAT_EPS
```

所有阈值比较必须走这四个函数，禁止裸 `==`。测试断言允许用 `pytest.approx(abs=1e-6)`，但**边界值断言**（B01/B02/B03/B05/B08）必须 `==`，因为实现里是精确赋值。
